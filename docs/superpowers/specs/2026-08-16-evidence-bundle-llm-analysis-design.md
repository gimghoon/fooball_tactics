# 코치 근거 묶음·LLM 분석 설계

## 목적

관리자가 코치 문서와 지정된 영상 구간을 근거 묶음으로 저장하고, LLM이 해당 자료만 사용해 전술 원칙 카드 초안을 생성하게 한다. 관리자가 카드별 근거와 내용을 직접 검수한 뒤 승인된 카드만 문제·애니메이션 초안 제작 단계로 보낸다. LLM 결과는 어떤 경우에도 자동으로 훈련 정답이나 공개 콘텐츠가 되지 않는다.

## 사용자와 권한

MVP의 자료 관리자는 사이트 운영자 한 명이다. 기존 팀원용 닉네임 입장과 관리자 인증을 분리한다. `/admin/evidence`와 관련 API는 사이트 로그인 사용자 중 서버 환경 변수에 등록된 관리자 ID만 접근할 수 있다. 일반 팀원은 원본 자료, 추출 텍스트, LLM 분석 결과, 미검수 카드에 접근할 수 없다.

검수 상태는 다음과 같이 분리한다.

- `analysis_draft`: LLM 분석 초안
- `owner_reviewed`: 운영자 1차 검수 완료
- `coach_reviewed`: 전문 코치 2차 검수 완료
- `held`: 근거 부족 또는 판단 보류
- `rejected`: 제외

MVP 공개 조건에는 최소 `owner_reviewed`가 필요하다. 향후 전문 코치 검수가 도입되면 화면에서 `owner_reviewed`와 `coach_reviewed`를 명확히 구분한다. 전술 카드 승인과 훈련 문제의 애니메이션·설명 승인은 별도 단계로 유지한다.

## 근거 묶음 입력

근거 묶음 하나에는 다음 정보를 저장한다.

- 묶음 제목과 분석 목적
- 자료 작성자 또는 코치 이름
- 발행일, 자료 유형, 신뢰 수준
- 사용 권한 메모와 출처 URL
- 운영자가 찾고 싶은 전술 상황과 관찰 메모
- 하나 이상의 PDF, TXT 또는 Markdown 파일
- 하나 이상의 HTTPS 영상 URL과 시작·종료 타임코드
- 영상 구간에서 관찰할 선수·공간 메모

PDF·텍스트 파일은 직접 업로드하고 영상은 URL과 타임코드만 등록한다. 원본 영상 파일 업로드, 인터넷 자동 수집, OCR이 필요한 스캔 PDF 자동 처리는 MVP에서 제외한다.

## 관리자 화면 흐름

`/admin/evidence`는 네 단계 마법사로 구성한다.

1. **자료 정보:** 제목, 작성자, 발행일, 신뢰 수준, 권한, 출처, 분석 목적을 입력한다.
2. **근거 추가:** 문서를 업로드하고 영상 URL·타임코드·관찰 메모를 추가한다.
3. **분석 확인:** 분석 대상 목록과 누락·중복 경고를 확인한 뒤 `분석 시작`을 누른다.
4. **카드 검수:** 원본 근거와 LLM 전술 원칙 카드를 나란히 보고 카드별로 승인·수정·보류·제외한다.

자료는 먼저 임시 저장한다. 저장 직후 자동 분석하지 않고 관리자가 자료 구성을 확인한 뒤 수동으로 분석을 시작한다. 분석 작업 상태는 `대기`, `분석 중`, `검수 대기`, `완료`, `실패`로 표시한다. 브라우저를 닫아도 서버의 작업 상태와 결과는 유지한다.

## 저장 구조

- R2는 원본 PDF·TXT·Markdown 파일과 추출 텍스트 산출물을 저장한다.
- D1은 근거 묶음, 자료 메타데이터, 영상 구간, 분석 작업, 전술 원칙 카드, 근거 연결, 검수 이력과 버전을 저장한다.
- 브라우저 저장소는 작성 중인 비권위 UI 상태에만 사용하고 자료·분석 결과의 원본 저장소로 사용하지 않는다.
- LLM 자격 정보와 파일 저장 자격 정보는 서버에만 두며 브라우저에 전달하지 않는다.

Sites 설정에는 논리 R2 바인딩 `EVIDENCE_FILES`를 추가한다. LLM 호출은 `EvidenceAnalyzer` 서버 인터페이스 뒤에 격리하고, MVP 배포에서는 서버 환경 변수로 공급된 API 키와 고정된 모델 식별자를 사용한다. 모델명이나 제공자별 응답 형식은 도메인 카드 저장 형식에 직접 노출하지 않는다.

자료 파일은 콘텐츠 해시와 임의 저장 키를 사용한다. 원래 파일명은 표시용 메타데이터로만 보존한다. 분석 작업에는 사용한 파일 해시, 영상 구간 버전, 분석 모델 식별자, 프롬프트 버전과 결과 스키마 버전을 기록한다. 동일한 자료 버전과 설정의 중복 분석은 하나의 작업 ID로 합친다.

## 비동기 분석 파이프라인

분석은 근거 묶음 단위의 비동기 작업으로 실행한다. MVP는 별도 메시지 큐를 요구하지 않고 D1 작업 레코드와 단계별 lease를 사용한다. `분석 시작` 요청은 작업을 생성한 뒤 서버의 후속 실행으로 첫 단계를 시작한다. 각 단계는 완료 결과와 다음 단계를 D1에 기록하고 제한 시간 안에 종료한다. 실행이 중단되거나 lease가 만료되면 동일 작업 ID가 마지막 완료 단계부터 재개된다. 관리자 화면의 폴링은 상태 표시용이며 브라우저가 열려 있어야 작업이 유지되는 구조로 만들지 않는다.

1. 업로드 자료의 형식과 무결성을 검사한다.
2. PDF·텍스트 문서에서 페이지 또는 문단 단위의 근거 청크를 만든다.
3. 영상 구간 메타데이터와 운영자 관찰 메모를 근거 청크로 정규화한다.
4. LLM이 각 청크에서 상황, 조건, 수비 형태, 관찰 단서, 행동, 결과, 예외를 추출한다.
5. 추출된 근거만 사용해 여러 개의 전술 원칙 카드 초안을 생성한다.
6. 구조화 결과를 스키마로 검증하고 유효한 카드만 `analysis_draft`로 저장한다.
7. 관리자가 원문 근거와 카드를 비교해 개별 검수한다.

한 번에 근거 묶음 하나를 분석하는 단순한 작업 처리부터 시작한다. 실패한 작업은 같은 작업 ID와 입력 버전으로 중복 없이 재시도한다. 일부 자료만 실패하면 성공한 카드와 실패한 자료를 구분해 표시한다.

## LLM 입력과 출력 계약

LLM 분석은 두 단계로 분리한다.

### 1. 근거 추출

각 문서 페이지·문단과 영상 구간에서 다음 필드를 추출한다.

- 전술 상황
- 공격·수비 조건
- 관찰 단서
- 행동과 예상 결과
- 예외 조건
- 원본 근거 위치

### 2. 전술 원칙 카드 생성

전술 원칙 카드는 다음 정보를 가진다.

- 상황과 적용 조건
- 여섯 수비 유형 중 하나
- 관찰해야 할 단서
- 권장 행동과 이유
- 허용 가능한 차선 행동과 이유
- 위험한 행동과 이유
- 문서 청크 또는 영상 타임코드 근거 목록
- `high`, `medium`, `low` 확신도
- 불확실성 및 자료 간 충돌 목록
- 문제·애니메이션 초안 생성 가능 여부

모든 행동과 이유에는 한 개 이상의 근거가 필요하다. 제공된 근거 밖의 일반 전술 지식은 카드 정답에 추가하지 않는다. 자료가 충돌하면 하나를 임의 선택하지 않고 충돌 내용을 기록한다. 조건이 다른 원칙은 별도 카드로 분리한다. 빈 근거, 잘못된 출처 참조, 낮은 확신도 또는 미해결 충돌이 있는 카드는 자동 승인할 수 없다.

## 운영자 검수

운영자는 카드별로 `승인`, `직접 수정 후 승인`, `근거 부족`, `제외`를 선택한다. 승인 전 다음 항목을 모두 확인한다.

- 근거가 결론을 실제로 뒷받침한다.
- 상황 조건과 예외가 빠지지 않았다.
- 패스·드리블·이동 선택 이유가 명확하다.
- 다른 선택이 가능한 경우 차선 행동으로 기록됐다.
- 원칙이 결정적 애니메이션으로 표현 가능하다.

운영자가 카드 내용을 수정하면 수정 전 LLM 초안과 수정 후 내용을 함께 보존한다. 승인에는 관리자 ID, 승인 시각, 근거 묶음 버전과 카드 스냅샷을 기록한다. 근거 파일, 영상 구간 또는 관찰 메모가 변경되면 해당 버전에서 생성된 분석과 승인을 `오래된 분석`으로 표시하고 문제 초안 전환을 차단한다.

승인된 카드는 바로 공개하지 않고 `문제 초안 만들기` 단계로만 이동한다. 생성된 문제는 기존 `sourceReviewed`, `timelineReviewed`, `explanationsReviewed`, 출처·검수자·검수 시각·검수 스냅샷 조건을 모두 통과해야 공개된다.

## 파일 보안과 삭제

- 허용 형식은 PDF, TXT, Markdown이며 파일당 최대 크기는 20MB다.
- 확장자, MIME 유형과 파일 시그니처를 함께 검사한다.
- 실행 파일, 압축 파일과 암호화 PDF는 거부한다.
- 영상 URL은 HTTPS만 허용하고 시작 시간이 종료 시간보다 작아야 한다.
- 관리자만 원본 파일을 내려받거나 분석 결과를 볼 수 있다.
- 파일 삭제 시 원본과 파생 텍스트를 함께 삭제한다. 연결된 카드나 문제 초안이 있으면 영향 대상을 먼저 표시하고 즉시 삭제를 막는다.
- 모든 업로드, 분석 시작, 재시도, 카드 수정과 승인 작업에 관리자와 시각을 기록한다.

## 실패 처리

- 업로드 일부가 실패하면 성공한 파일을 보존하고 파일별 재시도를 제공한다.
- 텍스트 추출 실패는 자료 단위로 표시하며 다른 자료의 분석을 유지한다.
- LLM 시간 초과 또는 일시 오류는 동일 작업 ID로 재시도한다.
- LLM 결과가 출력 스키마에 맞지 않으면 카드를 저장하지 않고 제한된 횟수만 재시도한다.
- 재시도 후에도 실패하면 원본 자료를 보존하고 구체적인 실패 단계를 관리자에게 표시한다.
- 자료 변경 또는 분석 설정 변경은 새 버전을 만들고 이전 승인을 자동 무효화한다.

## 테스트 및 승인 기준

- 관리자만 자료 화면과 업로드·분석·검수 API에 접근할 수 있다.
- PDF·TXT·Markdown 형식, 20MB 경계, MIME·시그니처 불일치를 검증한다.
- HTTPS 영상 URL과 시작·종료 타임코드 경계를 검증한다.
- 동일 파일 중복 업로드와 동일 분석 중복 실행을 방지한다.
- 근거 없는 주장, 빈 근거, 잘못된 출처 참조를 카드 저장 또는 승인 단계에서 차단한다.
- 낮은 확신도와 자료 충돌이 있는 카드는 자동 승인되지 않는다.
- 자료 변경 후 이전 카드와 승인 상태가 무효화된다.
- LLM JSON 오류, 시간 초과, 일부 자료 실패와 재시도를 검증한다.
- 승인 카드만 문제 초안으로 이동한다.
- 문제 초안은 기존 코치 검수·애니메이션 검수 게이트를 우회하지 못한다.
- 일반 팀원용 API와 화면에 원본 파일, 추출 텍스트, LLM 카드와 미검수 문제 데이터가 노출되지 않는다.

## MVP 범위 제외

- 원본 영상 파일 업로드
- 인터넷 자동 수집 및 자동 출처 선정
- 여러 관리자의 동시 편집
- 전문 코치 초대와 전자서명
- LLM 결과 또는 문제의 자동 공개
- 스캔 PDF OCR
- 일반 사용자용 전술 제작기
